## Objective
Create a gentle, clear onboarding flow for notification permissions that explains the value.

## Acceptance Criteria
- [ ] Show permission request at first medication with schedule
- [ ] Explain value before requesting (clear, minimal copy)
- [ ] Handle permission denial gracefully
- [ ] Provide "Not now" option (show again later)
- [ ] Deep link to system settings if permanently denied
- [ ] Visual design matches Phase 1 premium aesthetic
- [ ] Haptic feedback on permission grant

## Implementation Details

### Onboarding Screen
```
┌─────────────────────────────────────┐
│                                 │
│    🔔 Reminders                 │
│                                 │
│    Get notified when it's time    │
│    for your medications.           │
│                                 │
│    We'll never spam you -         │
│    just your scheduled doses.      │
│                                 │
│                                 │
│    [ Allow Notifications ]         │
│    [ Not Now ]                   │
│                                 │
└─────────────────────────────────────┘
```

### Onboarding Logic
- Show when:
  - User adds first medication with a schedule
  - Permission not granted yet
- Don't show again if:
  - User granted permission
  - User selected "Not Now" and hasn't added new meds

### Permission Denial Handling
```
┌─────────────────────────────────────┐
│                                 │
│    Notifications Disabled           │

│    You won't receive reminders    │

│                                 │
│    [ Go to Settings ]            │
│    [ Maybe Later ]               │

└─────────────────────────────────────┘
```

### Storage
